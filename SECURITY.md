# Security Policy

## Supported versions

Security fixes are provided for the latest maintained version on the default branch unless a release-support policy is published here.

| Version | Supported |
| --- | --- |
| Latest default branch | Yes |
| Older releases | No guarantee |

Update this table when the project adopts a formal release policy.

## Reporting a vulnerability

Do not disclose vulnerabilities in public GitHub issues, discussions, or pull requests.

Use GitHub's **Report a vulnerability** action under the repository's Security tab to submit a private report. If private vulnerability reporting is unavailable, contact **[INSERT SECURITY CONTACT EMAIL]**.

Include:

- A clear description of the issue and its potential impact.
- Affected versions, commits, or deployment configurations.
- Reproduction steps or a proof of concept.
- Any suggested mitigation.

Do not include real user data, production credentials, or secrets in the report.

## Response

The maintainers will acknowledge reports as soon as reasonably possible, investigate the issue, and coordinate a fix and disclosure timeline with the reporter.

Do not publicly disclose the issue until a fix or coordinated disclosure plan is agreed.
